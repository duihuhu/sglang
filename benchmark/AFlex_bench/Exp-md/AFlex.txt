一、Evaluation Setup（实验配置）
────────────────────────────────────────────────────────────────────────────────

1.1 硬件环境
    - GPU: 8× NVIDIA H800 80GB SXM
    - GPU 频率档位: 210 / 450 / 690 / 930 / 1170 / 1410 MHz
    - 互联: NVLink + InfiniBand (mlx5_4)
    - 实验分组: 4卡实验 GPU 4-7 / 8卡实验 GPU 0-7
    - 能耗采集: NVML nvmlDeviceGetTotalEnergyConsumption

1.2 软件环境
    - Python ≥ 3.10, CUDA 12.9, PyTorch 2.9.1
    - FlashInfer 0.6.6, Transformers 5.3.0
    - 推理框架: SGLang (修改版，支持 AFlex PDAF + Tier DVFS)

1.3 模型
    - Qwen3-32B (64层, hidden=5120, kv_heads=8)

1.4 测试方案
    ┌──────────────────┬──────────────────────────────────────────────────────┐
    │ 方案             │ 说明                                                 │
    ├──────────────────┼──────────────────────────────────────────────────────┤
    │ PDAF+Tier (Ours) │ PD+AF算子分离 + Tier1资源规划 + Tier2逐batch DVFS    │
    │ PD DP2+Tier      │ PD分离+2路DP，BiScale风格调频 (Baseline 1)          │
    │ Native DP4+Tier  │ 原生4路DP，DynamoLLM风格调频 (Baseline 2)           │
    │ Max Freq         │ 各方案锁定最高频率运行 (能耗上界)                    │
    └──────────────────┴──────────────────────────────────────────────────────┘

1.5 SLO 配置
    - TTFT SLO: 2000ms (纯处理时间，去排队延迟)
    - TPOT SLO: 150ms

1.6 评测指标
    - TTFT / TPOT / Throughput (tok/s)
    - Total Energy (J) / Energy Saving (%)
    - SLO Violation Rate (%)


二、Micro-benchmark（定长数据集）
────────────────────────────────────────────────────────────────────────────────

目的: 固定序列长度，消除长度波动干扰，精确刻画各方案能效特征。

2.1 数据集配置
    - 均衡:        IL=512,  OL=128,  QPS=1/2/4/6
    - Prefill-heavy: IL=2048, OL=256, QPS=1/2/4
    - Decode-heavy:  IL=256,  OL=512, QPS=1/2/4/6
    - 长输入:       IL=1024, OL=128,  QPS=1/2/4/6

2.2 实验设计
    - 4卡: 三种频率模式 (tier1_freq / max_freq / auto_freq) 对比
    - 8卡: 四方案 (PD TP4 / PD DP4 / PDAF DynM / PDAF Tier+DynM) 对比

2.3 关键结论
    [1] Tier1 稳定省电 ~30% (均衡/长输入 26-34%)，0% SLO违背
    [2] auto_freq ≈ max_freq：持续负载下硬件自动boost，"不干预"≈"锁最高频"
    [3] Tier 在 prefill-heavy 负载最优 (IL2048/4096 省 35-37%)
    [4] Decode-heavy 负载 Tier 几乎无收益 (memory-bound, 对频率不敏感)

3.2 关键结论

    三方案 Tier 节能百分比 (vs 满频):

    └─────────────────┴────────┴─────────┴───────┘

    PDAF+Tier 绝对能耗最低 (Tier 后, kJ):
    ┌─────────────────┬────────┬─────────┬───────┐
    │ 架构            │ steady │ varying │ heavy │
    ├─────────────────┼────────┼─────────┼───────┤

    [3] PDAF 不适合长 IL trace (TP=1 无法在 SLO 内处理 IL>2000)
    [4] DVFS 用延迟换能耗: PDAF proc TTFT 115→535ms, Native 157→237ms


四、Sensitivity（敏感度分析）
────────────────────────────────────────────────────────────────────────────────

目的: 变换关键参数，分析系统能效与 SLO 对参数变化的敏感度。

4.1 SLO 阈值联合扫描 (8×8 Grid)

    TTFT SLO (ms): 1000 / 500 / 450 / 400 / 350 / 300 / 200 / 100
    TPOT SLO (ms):  200 / 150 / 140 / 130 / 120 / 100 /  90 /  80
    共 64 组合 × 2 scheme (V2 DVFS + Baseline满频) = 128 次测试

    关键发现:
    [1] V2 调频模型有效区间远大于 V1: V2在SLO≥90ms可用, V1仅SLO≥250ms
    [2] TTFT SLO 主导 Prefill 频率, TPOT SLO 主导 Decode 频率, 基本正交
    [3] TPOT SLO 临界点 ~100ms (系统底噪约83ms), ≤80ms不可行 (>93%违背)
    [4] 宽松 SLO 节能 ~28%, 极紧 SLO(TPOT=80) 节能降至 ~15%

4.2 微批数 M 扫描

    ┌───────────────────┬─────────────────────────────────────────────────┐
    │ 配置              │ 结论                                            │
    ├───────────────────┼─────────────────────────────────────────────────┤
    │ M=1               │ 无流水线, 低通信开销, 小batch最优               │
    │ M=2 (interleaved) │ 大batch下 +58% 吞吐, 整体最优                  │
    │ M=3               │ 通信次数增加, 反而更差                          │
    │ DynM (动态)       │ 小batch走M=1, 大batch走M=2, 自适应最优          │
    └───────────────────┴─────────────────────────────────────────────────┘


五、Ablation（消融实验）
────────────────────────────────────────────────────────────────────────────────

目的: 以 AFlex 完整方案为基准，逐一移除组件，验证每个设计的必要性。

    ┌──────────────────┬─────────────────────────────────────────────────────┐
    │ 消融目标         │ 关键结论                                            │
    ├──────────────────┼─────────────────────────────────────────────────────┤
    │ 移除 Tier1       │ G=4时Tier1求解器INFEASIBLE, 节能主要来自Tier2;     │
    │ (资源规划层)     │ 需G≥8才体现资源重规划价值                          │
    ├──────────────────┼─────────────────────────────────────────────────────┤
    │ 移除 Tier2       │ 节能主要来自Tier2逐batch DVFS; V2耦合预测模型      │
    │ (逐batch DVFS)   │ 显著优于简单策略                                   │
    ├──────────────────┼─────────────────────────────────────────────────────┤
    │ 替换 IPC→UCX     │ CUDA IPC小张量延迟更低, 是AF分离的关键优化         │
    │ (通信后端)       │                                                     │
    ├──────────────────┼─────────────────────────────────────────────────────┤
    │ 移除 AF 分离     │ AF通信开销 ~75-95ms/iter, 拖低吞吐40-60%;         │
    │ (退化为PD)       │ 但换取了算子级频率解耦 → 更大节能空间              │
    └──────────────────┴─────────────────────────────────────────────────────┘


六、Reshard Breakdown（时延拆解）
────────────────────────────────────────────────────────────────────────────────

目的: 对系统环节做细粒度时延拆解，回答"时间花在了哪里"。

6.1 D-Stage Pipeline Breakdown

    逐层、逐微批的 Attention/FFN 计时分析:
    [1] DA/DF 执行不同调度, ~67% forward 时间在等待 UCX 传输
    [2] GPU 实际利用率仅 ~33%
    [3] M=3 时 2次串行UCX传输 + DA/DF无overlap, 传输延迟主导

6.2 DVFS 决策准确性

    解析逐迭代 DVFS 决策日志:
    [1] 预测器系统性低估 decode 迭代时间 ~28%
        (未充分计入 pipeline drain / IPC 同步开销)
    [2] 但决策方向正确 (按负载选频), SLO 余量充足未造成违背
    [3] 说明模型有改进空间, 但当前已可用于实际部署


================================================================================
                              总结
================================================================================

AFlex 通过 PDAF (PD+AF算子分离) + 两层DVFS (Tier1资源规划 + Tier2逐batch调频)
实现了 LLM 推理的能效优化:

  • 节能效果: PDAF+Tier 稳定节能 27-30%, 绝对能耗比 Native DP4 低 32-35%
  • SLO 保障: 在合理 SLO 配置下 (TTFT≥300ms, TPOT≥100ms) 违背率接近 0%
  • 关键权衡: 以 TTFT 延迟增加换取能耗降低 (proc TTFT 115→535ms)
  • 适用场景: 中等长度输入 (IL<2000), 对延迟容忍度适中的在线推理场景
  • 局限性: TP=1 限制了长输入处理能力; AF通信开销限制吞吐上限
