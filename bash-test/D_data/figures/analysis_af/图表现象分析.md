# D_data Decode：`analysis_af` 图表现象说明

本文档说明 `analyze_d_data_plots.py` 生成的各张图在**看什么**、以及在本数据集上**通常能观察到的现象**。其中 **图 2** 使用**含全部 `output_len` 档位的行**；**图 1** 在 **`output_len=4096`**（`BATCH_PLOT_OUTPUT_LEN`）上扫 `batch_size`；**图 3、4、5、6 及后续**在 **`output_len=512`** 子集上绘制（`FIXED_OUTPUT_LEN`）。若你更新了 `D_data.csv`，具体数值会变化，但坐标轴与解读方法仍适用。

**共同前提（与脚本一致）**

- 超长 `input_len`（32000/40000）已排除。
- **图 1**：仅 **`output_len=4096`**；**图 3、4、5、6、7、8、9、10**：**`output_len=512`**；**图 2** 为全 `output_len` 档位（见上文）。
- **图 1、3、4 的固定频率切片**为 **`gpu_clock=210`**（若 CSV 中不存在 210 则回退，见 `_facet_plot_clock` / `_trend_slice_clock`）。
- **图 5**：横轴为 **CSV 中出现的所有 `gpu_clock`**（本数据中一般为 210～1410 MHz 等多档），**不对单频采样**；子图条件为 **`batch_size=1`**。
- 当前筛选后的规模可参考同目录的 `summary_stats.txt`（例如 `n_rows`、`A`/`F` 范围等）。
- **按生成长度维度的汇总表**：见同目录 **`summary_by_output_len.csv`**（脚本每次运行会重写），与下面「output_len 维度」一节对应。

## 按 `output_len` 维度的数据表（`summary_by_output_len.csv`）

**与出图子集的关系**

- 多数图（图 3 起等）在脚本里使用 **`output_len=512`**；图 1 使用 **`output_len=4096`**；图 2 不固定（见上文）。
- **`summary_by_output_len.csv` 不固定 `output_len`**：在同样排除 `input_len ∈ {32000, 40000}` 后，**按 `output_len` 分组**，每个取值一行统计量，用于看 **Decode 生成长度** 对整体分布的影响。

**表中列含义（节选）**

| 列 | 含义 |
|----|------|
| `output_len` | 本行对应的 decode **目标生成长度**（token 数档位） |
| `n_rows` | 该 `output_len` 下样本条数 |
| `n_tp` / `n_gpu_clock` / `n_input_len` / `n_batch_size` | 该组内扫参覆盖的**不同取值个数**（非求和） |
| `A_*` / `F_*` | 单次 forward 中 A/F 块延迟（µs 量级，与 CSV 一致）的均值、标准差、最小、最大 |
| `F_over_A_*` | **F/A** 的比值分布（MLP 相对 Attention 谁更重） |
| `*_energy_mj_mean` | A/F 块能耗及 **total = A+F** 的样本均值 |
| `TPOT_ms_mean` | 该组内 **TPOT**（ms）样本均值，反映端到端每 token 时间量级 |

**如何读现象**

1. **随 `output_len` 增大**：Decode **步数更多**，总调度/内存行为变化；表中 **`TPOT_ms_mean` 通常上升**（生成更长）。**`A_mean_us` / `F_mean_us`** 若仍指「单步 forward 内 A/F」而非整段生成总时延，则更多反映 **固定一步下** 的算子耗时；若 CSV 定义是「整段累计」则需以表头/采集脚本为准。
2. **跨 `output_len` 比较 `F_over_A`**：可看出 **更长生成是否使 MLP（F）相对更主导** 或相反（与 KV cache、批处理、是否主要时间在 F 有关）。
3. **`n_rows` 与 `n_*` 覆盖**：若某 `output_len` **行数很少**或 **缺某些 tp/频率**，该行的均值**方差大、可比性弱**，解读时降权。
4. **与 `FIXED_OUTPUT_LEN=512` 图对照**：在 CSV 中找到 `output_len=512` 一行，其均值应与 `summary_stats.txt`（仅 512 子集）中的全局均值**接近**（同一子集定义下应一致；若 `summary_stats` 在过滤顺序上有细微差别，以脚本 `correlation_and_summary` 为准）。

## 图 1：`1_latency_AF_vs_batch_size` / `1_energy_AF_vs_batch_size`

**画法**

- 子图为网格：**行 = `tp`，列 = `input_len`**（由数据中出现过的取值组成）。
- 曲线：**横轴 `batch_size`（对数坐标 log₂）**；纵轴分别为 **A/F 延迟** 或 **A_energy_mj / F_energy_mj**。
- **仅 `gpu_clock=210`（或回退频率）** 一条频率切片。
- **固定 `output_len=4096`**（脚本常量 `BATCH_PLOT_OUTPUT_LEN`），与其它图使用的 `output_len=512` 子集不同。

**现象与解读**

- **延迟**：Decode 阶段单次 forward 里 **注意力块（A）与 MLP 块（F）** 的耗时；随 `batch_size` 增大，同一 `(tp,input_len)` 上往往呈现**先因并行度/规约效率变化、后因显存或调度**带来的非单调性（小到中等 batch 可能略升或略降，大 batch 可能再变）。
- **能耗**：总能耗量纲为 **mJ**；batch 增大通常使 **单步能摊薄的“单次请求”观测**变化，曲线形态不必与延迟完全同向（功率×时间积分）。
- **格子为空**：表示该 `(tp, input_len, 固定频率)` 组合在 CSV 中无行（例如本数据中 **`tp` 可能只有部分取值**，与全量扫 TP 的配置有关）。

## 图 2：`2_latency_AF_vs_output_len` / `2_energy_AF_vs_output_len`

**画法（与图 4 同类的 facet 风格，但横轴为 decode 长度）**

- 使用 **`D_data.csv` 全量**（仅排除超长 `input_len`），**不**限制 `output_len=512`。
- 子图网格：**行 = `tp`，列 = `input_len`**。
- 横轴 **`output_len`（log₂）**，即目标生成长度档位；纵轴为 **A/F 延迟** 或 **A_energy_mj / F_energy_mj**。
- 固定 **`gpu_clock=210`**（或 `_trend_slice_clock` 回退）；固定 **`batch_size=128`**（脚本常量 `OUTPUT_LEN_PLOT_BATCH_SIZE`），避免同一子图内混多条 batch 曲线。

**现象与解读**

- **更长 `output_len`** 表示 decode 阶段要跑更多步；若 CSV 里 A/F 是**单步 forward** 的块延迟，曲线可能**相对平缓**；若与整段生成耦合，则可能**随 `output_len` 上升**。
- **与 `summary_by_output_len.csv` 对照**：表中是按 `output_len` 聚合的**全局均值**，图 2 则保留 **(tp, input_len)** 切片，便于看 **不同上下文长度下** 生成长度缩放是否一致。
- 子图为空：该 `(tp, input_len, bs=128, 固定频率)` 在数据里无样本。

## 图 3：`3_latency_AF_vs_tp` / `3_energy_AF_vs_tp`

**画法**

- 子图为网格：**行 = `input_len`，列 = `batch_size`**。
- 横轴 **`tp`（张量并行度）**；纵轴为 A/F 或 A/F 能量。
- 固定 **`gpu_clock=210`**（或回退）；固定 **`output_len=512`**。

**现象与解读**

- **通信与划分**：`tp` 增大时，单层内矩阵并行增加，**单卡算量减少**但 **AllReduce 等通信增加**；A 与 F 中通信敏感程度不同，两条曲线可能**分离或交叉**。
- 在本数据切片上，例如在 **`input_len=512, batch_size=1, clock=210`** 一类的点，**A 随 `tp` 从 2→8 可能略降或趋稳**，反映并行对单步延迟的分摊；**F 的变化**还与 MoE/MLP 布局有关（与具体模型一致）。

## 图 4：`4_latency_AF_vs_input_len` / `4_energy_AF_vs_input_len`

**画法**

- 子图为网格：**行 = `tp`，列 = `batch_size`**。
- 横轴 **`input_len`（log₂）**，即 prefill/上下文侧长度在 decode 统计里对应的 **输入侧长度**；纵轴为 A/F 或能量。
- 固定 **`gpu_clock=210`**（或回退）。

**现象与解读**

- **`input_len` 增大**通常使 ** attention 计算与 KV 相关开销** 增长，**A** 往往**近似次线性或超线性上升**（取决于实现与是否已到长序列瓶颈）。
- **F** 若主要与**单步 decode token 生成**相关、对历史长度不敏感，则**相对平缓**；若实现中与序列长度耦合（如某些 layernorm/缓存路径），也会有可见上升。
- 同一图中比较不同 **`batch_size`** 列：可观察 **批处理对长度缩放曲线** 的影响（大 batch 可能改变内存带宽瓶颈）。

## 图 5：`5_latency_AF_vs_gpu_clock` / `5_energy_AF_vs_gpu_clock`

**画法**

- 子图为网格：**行 = `tp`，列 = `input_len`**；**`batch_size=1`**。
- 横轴 **`gpu_clock`（MHz）**，按数据中出现的档位连接为折线（本数据常见 **210～1410** 等多档）；纵轴为 A/F 或能量。
- **不固定为 210**，用于看 **频率扫描**。

**现象与解读**

- **频率升高**通常降低**同负载下的延迟**，故 **A、F 往往随 `gpu_clock` 增大而下降**（若未触及其它瓶颈，如 PCIe、CPU 或功耗墙）。
- **能耗**：更高频率可能 **单步时间变短但功率更高**，mJ **不一定单调下降**；若图中 **延迟明显下降而能量略升或持平**，属于常见取舍。
- 若某子图**只有一点**：说明该 `(tp,input_len,bs=1)` 只有一种 `gpu_clock` 的样本。

## 图 6：`6_heatmap_inputlen_batch`

**画法**

- 选取 **中间档 `tp`**（排序后的中位）；固定 **热图用频率**（优先 210，否则回退）。
- 四个子图：**A、F、A_energy、F_energy**；行 = `input_len`，列 = `batch_size`。

**现象与解读**

- 二维展示 **长度 × 批大小** 对 A/F 与其能耗的联合影响；**对角/高 batch、高 input_len** 角往往更“热”（更大数值）。
- 适合快速发现 **异常格子**（测量缺口、离群点或某一 `(input_len,batch)` 特别重）。

## 图 7：`7_scatter_batch_colored_clock`

**画法**

- 与 `main()` 中相同的过滤（含 **`output_len=512`**）后的数据；**batch_size–A / batch_size–F / 两路 energy** 的 **log–log 散点**；颜色为 **`gpu_clock`**。

**现象与解读**

- 展示 **全局尺度关系**：同一 batch 下不同频率点形成 **竖直方向“色带”**；同一频率下 batch 增大沿横轴延伸。
- 若存在明显 **分叉或带状结构**，多与 **频率档位与 TP 配置组合** 有关。

## 图 8：`8_ratio_F_over_A_vs_batch`

**画法**

- 对各个 **`tp`**，散点 **`F/A`** 对 **`batch_size`**（log₂ x 轴）。

**现象与解读**

- **Decode** 中若 **F（MLP）重于 A（Attn）**，则 **F/A &gt; 1** 的点会较多；摘要里 **F/A 中位数 &lt; 1** 说明在相当比例的配置下 **A 的延迟仍占主导**（与序列长度、头数、隐藏维等有关）。
- 随 **batch** 变化：并行与访存模式改变，**F/A** 可以**缓慢漂移**，反映两类算子缩放不一致。

## 图 9：`9_AF_iso_inputlen_bs_16384.png`

**画法**

- 仅 **`input_len × batch_size = 16384`** 的行；多 **子图块**：行向为 **tp**，列向为 **`gpu_clock`**；每格内三条纵排分别为 **A/F**、**TPOT_ms**、**能量**（脚本里字段名为 `TPOT_ms`，与 Decode 语义一致）。

**现象与解读**

- 在 **固定总算子强度（长度×批的乘积）** 下比较不同 **长度/批次拆分**，观察 **延迟与 TPOT、能量** 是否对 **形状（长×宽）** 敏感。
- 若 **TPOT** 随 `input_len`（在固定乘积约束下）变化明显，说明 **调度或 kernel 对“长而窄 vs 短而宽”批次** 的偏好不同。

---

## 图 10：`10_F_lat_210_over_1410_MHz_bs4.png`

**画法**

- 固定 **`batch_size=4`**；对每个 **`(tp, input_len)`**，若同时存在 **210 MHz 与 1410 MHz** 的 **F**，则画 **`F(210)/F(1410)`** 对 **`input_len`**。

**现象与解读**

- **比值 &gt; 1**：低频下 **F 更慢**（符合预期）；沿 `input_len` 若比值**持续大于 1 或缓慢变化**，说明 **频率敏感相对一致**。
- 若某些 **长度区间** 比值异常接近 1 或波动大，可能与 **功耗、频率是否真的锁定、或该长度样本缺失** 有关，值得核对原始 CSV。

## 数据注意事项（结合当前 CSV 的示例）

- 在 **`output_len=512`** 子集中，若 **`tp` 仅包含 {2,4,8}**，则 **图 1/3 等不会出现 `tp=1`**，解读时勿与全表混淆。
- 所有图为 **批测/扫参 CSV 的统计展示**，受 **锁频是否成功、重复次数、随机负载** 影响；与线上市内真实 SLA 需区分。
